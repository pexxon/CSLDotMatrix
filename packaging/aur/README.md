# Publishing csldotmatrix on AUR

This directory prepares the stable `csldotmatrix` package for v0.6.0. It is not
an AUR submission by itself. Only v0.5.0 existed when this packaging was prepared.

## Validate and release upstream

1. Review and commit the v0.6.0 application and packaging changes. Test on the
   actual cooler and a fresh Arch desktop login, including Settings stop/start,
   tray choices, logout/login, and migration from the manual install.
2. Use the [GitHub release workflow](../../docs/releases.md), or run
   `python3 tools/prepare_package.py --tag v0.6.0` from the repository root
   (Python 3.11+ and `makepkg`). This creates `dist/csldotmatrix-0.6.0.tar.gz`
   and matching `dist/PKGBUILD` / `dist/.SRCINFO` from an
   explicit source allowlist, excluding Windows binaries, captures, caches,
   and the PKGBUILD/checksum metadata itself. The generated metadata contains
   its exact SHA-256. Publish the repository changes and push tag `v0.6.0` to
   `https://github.com/pexxon/CSLDotMatrix`. Actions builds and attaches the
   **exact archive** and metadata to the GitHub release after passing tests.
   Do not substitute GitHub's autogenerated source
   archive or move an existing release tag. Publication requires approval.
3. Install Arch build dependencies: `base-devel`, `python-build`,
   `python-installer`, and `python-setuptools`. Runtime dependencies are
   `python`, `python-hidapi`, `pyside6`, and `systemd`.
4. From this directory run `makepkg -s`, then inspect the archive with
   `bsdtar -tf csldotmatrix-0.6.0-1-any.pkg.tar.zst`. Run `namcap` on the
   PKGBUILD and package when available. Prefer a clean-chroot build with
   Arch's `devtools` before publication.
5. Test installation with `sudo pacman -U ./csldotmatrix-0.6.0-1-any.pkg.tar.zst`
   on a test desktop. Check the installed CLI from outside the checkout.

The PKGBUILD uses a versioned GitHub release asset and a verified SHA-256,
with no `SKIP` checksums. Until that asset is uploaded, local builds can use
the archive by copying it beside the PKGBUILD before running `makepkg`:

```sh
# From the repository root:
python3 tools/prepare_package.py --tag v0.6.0
cd dist
makepkg -s
```

After release, test `makepkg --verifysource` against a fresh download to confirm
that the hosted bytes match. Bump `pkgver` for each upstream release, and
`pkgrel` for packaging-only changes.

The package installs:

- Console entry points into `/usr/bin` and the module into Python site-packages.
- A user service in `/usr/lib/systemd/user/csl-dotmatrix.service`.
- The permission rule in `/usr/lib/udev/rules.d/70-csl-dotmatrix.rules`.
- Menu entries in `/usr/share/applications` and session autostart in
  `/etc/xdg/autostart/csl-dotmatrix.desktop`.

Arch's systemd pacman hooks reload user units and udev rules and normally
retrigger devices. No package install script changes user home directories,
starts a root daemon, or launches a GUI. The desktop session helper enables
the user service only when no saved config exists. Existing users enable it
through Settings. First use requires a recognized CPU sensor; Intel/NVIDIA
and the new startup behavior still need hardware field testing.

## Submit the AUR repository

Create an AUR account and register an SSH public key. Verify that the name
`csldotmatrix` is available before submission. In a separate directory:

```sh
git clone ssh://aur@aur.archlinux.org/csldotmatrix.git
cd csldotmatrix
# Copy PKGBUILD and .SRCINFO from the GitHub release assets here.
makepkg --printsrcinfo > .SRCINFO
git add PKGBUILD .SRCINFO
git commit -m 'Initial csldotmatrix release'
git push origin master
```

An empty-repository warning is expected for a new AUR package. The AUR
repository contains build metadata, not a copy of the application or package
binaries. Regenerate `.SRCINFO` after every metadata change. Once the AUR push
succeeds, `yay -S csldotmatrix` can find and build the package.

References: [AUR submission guidelines](https://wiki.archlinux.org/title/AUR_submission_guidelines),
[Python package guidelines](https://wiki.archlinux.org/title/Python_package_guidelines),
[udev permissions](https://wiki.archlinux.org/title/Udev).
